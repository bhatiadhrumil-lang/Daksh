# Milestone 2 — Real Commerce Plan

## Scope

Launch-region decisions are now confirmed:

- Payments: Razorpay, India, INR.
- Database and hosting: Postgres, deployed on Vercel.
- Accounts: required for checkout and order history.
- Source of truth for catalog and inventory: Postgres, seeded from the Milestone 1 catalog, with the seed script as the temporary admin surface.

Core scope for this pass:

1. Isolated Postgres database, Drizzle schema, migrations, and seed.
2. INR pricing stored as integer paise, including catalog data and shipping thresholds.
3. Postgres-backed catalog reads for home, shop, product, and search.
4. Better Auth email/password accounts, session-gated checkout, account page, and order history.
5. Server-authored order and payment flow:
   - Validate cart and address on the server.
   - Recompute prices from Postgres; never trust client totals.
   - Create a Razorpay order for each payment attempt.
   - Verify the Razorpay payment signature server-side.
   - Verify amount, order, and payment status with Razorpay before fulfilment.
   - Process Razorpay webhooks idempotently and validate the webhook signature.
6. Quality pass: lint, production build, browser smoke tests, documentation.

Deferred from this pass and still tracked as open in `REQUIREMENTS.md`:

- Admin UI, content management, and inventory purchasing tools.
- Transactional email provider for verification, password reset, and receipts.
- Live shipping-provider rates and tracking.
- Discounts, gift cards, returns workflow, analytics, consent, and legal pages.
- Production deployment and monitoring.

## Architecture

### Database

- Local Postgres 16 container, isolated from the existing `ecom-postgres` container.
- Local port `5433` to avoid colliding with the other project on `5432`.
- Drizzle ORM with `pg` Pool. One pool per process, cached on `globalThis` during development.
- Migrations generated by `drizzle-kit` and committed under `drizzle/`.
- Seed script upserts the 16 products and logs credentials-free counts.
- Auth tables: `user`, `session`, `account`, `verification`.
- Commerce tables: `products`, `orders`, `order_items`, `payment_attempts`, `webhook_events`.
- Order rows snapshot the delivery address, product name, variant, and unit price so later catalog edits cannot rewrite history.

### Catalog reads

- `src/lib/catalog.ts` is the server-only product repository.
- Cached catalog reads use `use cache` with `cacheTag("catalog")` and a short lifecycle.
- Existing storefront components receive plain `Product` objects, so client components do not import the database.
- The cart stores a minimal product snapshot in localStorage (`oasis-cart-v2`). Checkout always re-reads products from Postgres and recomputes totals.

### Authentication

- Better Auth with the Drizzle adapter and email/password enabled.
- `nextCookies()` is the final plugin so server actions can set cookies.
- API handler at `/api/auth/[...all]`.
- Account routes check the session on the server. Client-side cookie presence is never treated as authorization.
- Checkout and account components read the session behind a Suspense boundary, as required by Cache Components.
- Account page includes order history and a sign-out server action.

### Payments

- Create a local order in `pending_payment` status, then create a Razorpay order for the exact server total.
- Each retry creates a new Razorpay order; a unique local `payment_attempts` row stores the mapping.
- Razorpay Checkout opens from a server-returned order id and public key id.
- On completion, verify `razorpay_signature` with HMAC SHA256 over `${order_id}|${payment_id}`.
- Fetch the payment from Razorpay and require the expected amount, order id, and `captured` status before marking the local order paid.
- Marking an order paid is idempotent. Inventory is decremented once inside the same transaction.
- Webhooks validate `x-razorpay-signature` against the raw request body. Event ids are stored to prevent duplicate processing. `payment.failed` updates only the payment attempt.
- Missing Razorpay environment variables disable payment with a clear error; no fake “paid” state is allowed.

### Money and tax

- All money is an integer number of paise.
- INR prices are converted from the Milestone 1 USD catalog at a documented reference rate and rounded to a sensible rupee amount.
- Displayed prices are treated as GST-inclusive until a tax configuration is supplied. No separate tax line is added.
- Free standard delivery threshold and delivery prices are INR constants.

Browser smoke tests:

- Home, shop, product, and search render from Postgres.
- Cart add/update/remove persists with the new snapshot format.
- Unauthenticated checkout redirects to login.
- Register, sign in, account page, and order history.
- Checkout with missing Razorpay keys returns a clear payment-unavailable state.
- Webhook rejects an invalid signature and accepts a valid signed fixture.
- No console errors, failed images, or broken layouts at desktop and 390 px.
